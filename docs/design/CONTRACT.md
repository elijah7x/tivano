# Tivano 设计契约

这份契约记录 Tivano 已经确定的设计原则和规则，是 Agent 和贡献者做界面改动时的主要参考。

- 它不是逐条执行的规范。遇到没写到的情况，按第一、二节的判断方式推演。
- 只收已经确定的内容。仍在探索的方向不写进来。
- 本文写到的已否决形态，再次提出前要先说明这次和上次有什么本质不同。
- 规则改变时，在同一个提交里更新本文。

## 一、产品立场

1. **小而美，界面本身就是竞争力。**
   - 宣发和截图一律用真实界面，不用手绘或示意的假窗口。
2. **用户包括不懂 Git 的普通人。**
   - 不假设用户懂 Git、worktree 或内部概念。
   - 判断一个页面时，先问：第一次来的人能看懂吗？
3. **能替用户决定的，就不交给用户。**
   - 优先给好的默认值和自动判断，而不是新增设置项。
   - 新增设置项需要说明：为什么没法替用户决定？
4. **新增的视觉和交互不能带来常驻开销。**
   - 页面不可见时不消耗性能。
   - 性能优化也不能以牺牲外观或交互为代价。

## 二、判断方式

1. **先看全局，再看局部。**
   - 一个控件放进整页、整个 App 之后是否和谐，比它单独好不好看更重要。
   - 同一角色的元素在各处必须一致；细节上的差异会让人觉得不用心。
2. **看肉眼，不看数值。**
   - 光学大小、线重、字重和对齐，以渲染后的样子为准。外框尺寸一致但看起来不一致，就要调。
3. **每个元素都要说得出存在理由。**
   - 界面上的文字是为了引导和帮助理解。不写没有信息量的字。
   - 可视化的图形必须和它表达的数据有关联。
4. **长期耐看比第一眼新奇重要。**
5. **先解决大问题，再抠细节。**
   - 先定方向、结构、色调和融入感，再处理像素级细节。
   - 必须修的错误和个人喜好分开处理。
6. **取舍顺序。**
   - 用户直觉与长期耐看 > 后续零维护负担 > 外观不变前提下的性能 > 新奇。

## 三、视觉

1. **减法优先。**
   - 能用留白就不用线，能隐藏到悬停时再出现，就不常驻。
   - 不重复显示同一信息，例如同一张卡片里出现两次 LOGO，或者上层已经筛选过、下层再筛一次。
2. **很少用分割线。**
   - 模块之间用留白和已有的卡片边界来分隔。
   - 不在模块内部加二级分割线。
   - 确实需要线时，左右缩进相等并对齐。
3. **呼吸感。**
   - 设置页功能板块之间的间距为 36pt，弹出层保持紧凑。
   - 宁可松，不要挤。
4. **温润，不锐利。**
   - 图标走温润、轻盈、扁平的方向，不要尖角、厚阴影和强立体感。
   - 精致不等于堆细节，不要锯齿和杂毛。
5. **颜色克制。**
   - 状态说明和占位提示用次要文字色，不用橙色或蓝色高亮，也不加粗。
   - 主题色不铺满整屏。
   - 强调色按具象的物体来命名，例如「牛油果绿」「珊瑚红」，不用品牌名。
6. **融合，不要贴图感。**
   - 元素和底色、玻璃材质融为一体，不放实色块、大头图或生硬的白框。
   - 侧栏和主区不互相穿插，界面不切成碎块。
7. **主题。**
   - 液态玻璃：macOS 26 以上。
   - 质感：不依赖液态玻璃，兼容更早的系统。
   - 创作：近白底、衬线字体、手绘图标，进入时使用低饱和的珊瑚红。
   - 应用图标随主题切换。

## 四、组件

1. **一种角色，一种组件，一个尺寸。**
   - 复用 `ChromeSection`、`ChromeCard`、`ChromeRow`、`GlassPickerButton`、`ChromeVisualPicker`、`SettingsSwitch` 和全站统一的模型选择器。
   - 不把一个选择拆成多行或多个药丸。
2. **动作按钮（药丸）。**统一用 `.chromePillButton()`。
   - 常规（28pt，与选择器等高）用于所有动作：行内、卡片和区块标题、卡片正文、空状态，以及弹窗、面板底部。
   - 紧凑（`.compact`，24pt）只用于本身比行标题低一级的小字行，例如额度报错、重置次数的子行。
   - 窗口顶栏的胶囊保持 32pt（`ChromeTextButton`、`ChromeCapsule`），不用在页面内容里。
   - 纯图标按钮用 `iconOnly`，画成同高的正圆。
   - 不再用 `controlSize`、系统玻璃按钮的默认尺寸，或给按钮标签写死高度来决定按钮大小。
3. **危险操作。**
   - 平时和普通按钮一样，指针移上去变红。
4. **选择器的行为。**
   - 按钮宽度随内容变化，不按最长的选项占位。
   - 选完模型后浮层不关闭，方便接着调推理强度。
   - 箭头只跟在它打开或切换的对象后面：推理强度卡里，箭头跟模型名（点开换模型），推理强度是滑块的标签，不带箭头。
   - App 退到后台时，浮层自动收起。
   - 界面 chrome 和输入区按钮的浮层统一用 `anchoredPopover`（锚定到按钮一次的 AppKit popover），不用 SwiftUI `.popover`，因为 SwiftUI 会对已打开的浮层重新锚定，长时间运行的窗口会出现漂移。
5. **折叠箭头。**
   - 放在标题右侧。
   - 收起时常显，展开时只在悬停时出现。
6. **对话顶栏与百宝箱。**
   - 分支 / worktree 状态常驻对话顶栏，不收折。
   - 设置按钮右侧的百宝箱（`square.grid.2x2`）以固定尺寸的纯悬浮玻璃层叠在消息流之上，不切分主栏、不改变消息流或输入区排版；关闭时完全卸载、零常驻开销。
   - 百宝箱统一收纳本对话产出物（由 macOS 默认应用打开）、变更 / Git 与双模式终端（可停靠底部或收进百宝箱）。

## 五、交互

1. **丝滑跟手是底线。**
   - 滚动不跳、不闪，不和触控板抢滚动。
   - 光标形状不能出错。
   - 发出的消息立刻出现。
2. **状态必须诚实可见。**
   - 卡住、额度用尽、等待输入、并发上限、后台失败，都要给出明确的提示，但尽量不打扰。
   - 不吞掉报错。
3. **不打扰，不擅自做主。**
   - 不自动弹出登录页，不在后台悄悄换模型。
   - 用户已经明确表达的意图，不再要求二次确认。
4. **符合直觉。**
   - 看起来能拖的就允许拖，但不额外加拖动手柄。
   - 弹出的面板挂在触发它的元素旁边。
   - 本地文件链接用默认应用打开。
5. **少一层就少一层。**
   - 能在卡片内展开的，就不进子页，也不弹窗。
   - 不为一个子功能新开整页。
   - 不为一个功能去改动无关模块的现有交互。

## 六、文案

1. **讲人话，也要书面。**
   - 不用内部黑话，也不过度口语化。
2. **准确。**
   - 描述和实际行为一致。
3. **不用内部代号。**
   - 面向用户统一叫子代理、模型搭配、角色、服务商配置、模型选择。
   - 术语以 `docs/i18n/CONVENTIONS.md` 为准。
4. **不写没有信息量的字。**
   - 占位文字、欢迎语、装饰性的标签，先问它承担什么信息。

## 七、交付与验收

1. **探索阶段先给能对比的渲染稿。**
   - 用浏览器里的 HTML 给出多套方案，方案要放在真实语境里，带完整界面和真实材质。
   - 不交线稿。
   - 方向选定后，用假数据起一个隔离的 App 实例，覆盖长和短、空和满等状态。
2. **交付前自查。**
   - 先自己看过渲染结果再交付。
3. **按全局修，不挤牙膏。**
   - 修一处时，把同类问题一起找出来、一起改。
4. **落地忠于批准的原型。**
   - 实现与已经批准的原型不一致时，先停下来说明。

## 八、已否决的形态

| 形态 | 理由 |
|---|---|
| 把一个选择拆成多行或多个药丸 | 和全站的单按钮选择器不一致 |
| 按最长选项固定宽度的选择器按钮 | 把旁边的说明挤到换行 |
| 状态文字用彩色高亮或加粗 | 刺眼，抢按钮的视觉重心 |
| 模块内的二级分割线、卡片顶部的分割线 | 把界面切碎 |
| 重复显示的 LOGO、二级筛选 | 信息重复 |
| 割裂成多张卡片的同一栏 | 割裂 |
| 实色天气窗、大块天空头图、吊线娃娃 | 贴图感，不和谐 |
| 多层托盘 | 层级繁复 |
| 和数据没有关联的可视化 | 没有意义，看久了累 |
| 设置页的搜索框 | 页面精简后不需要 |
| 自动弹出的登录页、在后台悄悄换模型 | 打扰用户，擅自做主 |
| 「建议」行、「跳过」这类表意不清的附加控件 | 多余 |
| 用手绘假窗口做宣传素材 | 不真实 |
