## Security notes

- **Local Control has a same-account boundary, not a secret-token boundary.** `ControlSocket.swift` checks private directory ownership/type/mode with `lstat`, creates directories as 0700, binds a 0600 socket, uses an exclusive no-follow lock file, checks peer UID on both client and server, sets close-on-exec and suppresses SIGPIPE. Edition and instance checks prevent accidental cross-instance routing; their UUID is public in the handshake.
- Control request input is byte-framed, capped before decoding and limited to eight connections with a 30-second deadline. Pending handler admission is bounded. Stop revokes transports; already accepted App operations deliberately continue. App command allowlists, text validation and mutation authorization remain for the lead to audit in `App/Control`.
- `ControlHistoryReader.readBounded` rejects final-component symlinks/nonregular files, limits file size and checks growth during reads. UUID-derived filenames avoid user-controlled relative paths. Ancestor replacement by the same UID remains outside the stated isolation boundary. History text truncation can cut a UTF-8 code point and produce a replacement character; this is presentation fidelity, not broken wire JSON.
- CLI installer recognizes only owned symlinks matching the helper/receipt before replacement. Its code explicitly acknowledges the same-UID race between checking and publication. No shell command interpolation is used there.
- **MCPProxy has a weaker boundary than Local Control.** It binds loopback TCP, but the inspected request path has no per-client credential, peer-UID check, Host allowlist or Origin check. A local process that can reach a known route can use upstream credentials injected by the proxy. Loopback alone does not isolate other local accounts. Browser/DNS-rebinding exploitability was not tested. Owner decision: require a per-installation capability and origin/host restrictions, with provider-config migration; do not infer protection from Local Control's socket checks.
- MCP routes come from registered configuration rather than an arbitrary request URL, which limits request-selected destinations. This does not replace client authentication.

## Observations

- `Shell.run` drains stdout and stderr concurrently, uses a one-shot continuation, supports cancellation and terminates tracked descendants with escalation. Git uses this off-main executor, lane admission and operation deadlines; no wait-before-drain bug was found in those paths.
- `StdioFramer` accumulates bytes before JSON decoding, so split multibyte UTF-8 and partial reads do not inherently corrupt messages. It caps individual frames at 16 MiB. `StdioProcess` also caps input queue, raw ingress backlog and stderr tail. The decoded object graph can exceed the raw-byte budget.
- `MCPWire` already uses a dedicated cancellable session, a timeout, bounded ordinary responses and a byte-based SSE event parser supporting CR/LF, BOM and joined data fields. MCPProxy and OpenAI-compatible parsing do not inherit those safeguards.
- Git dirty-path, diff-name and several tree operations use NUL-delimited output, including both rename paths. The status summary uses porcelain v2 and counts records without extracting paths; it was not changed merely because it lacks `-z`.
- DiskWriter coalesces pending snapshots per file and uses atomic writes. Turn files retain prior revisions until head publication, then prune. Atomic per-file replacement is not a multi-file fsync durability guarantee.
- No `try!` appeared in the scoped pattern scan. Inspected force unwraps included guarded nonempty byte buffers, dictionary lookups from their own keys and a task group with children; those were not mechanically rewritten.
- Nowledge thread search: `Tivano local control socket`, default scope, limit 5, via `nmem`; relevant implementation threads were found, but no historical claim substitutes for current source evidence. Codebase indexing crashed, so discovery fell back to direct source searches.
- Lead validation remains entirely outstanding, including compilation, transfer cancellation, HTTP chunk decoding, control adversarial input and store crash/recovery scenarios. This report is not release acceptance or an exhaustive audit of every provider method.
