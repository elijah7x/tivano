## 实测性能

以下均为同机合成夹具，取三次热运行中位数；不代表真实会话的帧率、峰值内存或所有机器表现。

| 场景 | 修复前 | 修复后 | 解释 |
| --- | ---: | ---: | --- |
| 10,000 回合历史，更新一个回合并保存 | 157.1 ms | 39.3 ms | 约减少 75%；一次目录枚举替代逐文件存在性查询，复用本次枚举结果清理 |
| 1,000 回合历史，同上 | 15.5 ms | 5.3 ms | 保留缺失历史拒绝保存、先发布 head 再清理的顺序 |
| 100 回合历史，同上 | 2.47 ms | 1.05 ms | 未引入跨保存的存在性缓存 |
| 两张 3000×2400 PNG，发送准备期间主线程探针延迟 | 103 ms | 0.02 ms | 图片读取、缩图、base64 和 JSON 编码转到后台；探针不是帧率测试 |
| 上述图片的最终 JSON 载荷 | 57,666,629 B | 7,088,767 B | 减少 87.7%；原载荷超过 32 MiB 队列上限，新载荷可发送 |
| 上述图片准备总耗时 | 103 ms | 197 ms | 缩图增加 CPU 工作，但释放主线程并大幅减少载荷；不能称总编码更快 |

保存夹具使用真实 DiskWriter 和合成最小回合数据。图片夹具使用真实 Attachment 缩图及 Pi 编码入口，对照原始同步读取和编码路径；图片为确定性噪声，原图每张约 21.6 MB。OMP 复用同一图片准备路径，载荷保护另有运行时检查。

## 已修复的行为

| 范围与主要文件 | 用户可见结果 |
| --- | --- |
| `ACPSession`、`PiSession`、`OmpSession`、`ClaudeSession`、`CopilotSession` | 模型切换、模式设置或图片准备时 Stop 会取消本次发送；旧准备完成后不再发送请求。准备期间关闭 CLI，下轮由运行时重建连接。Copilot 已结束命令的迟到结果不能启动新 prompt。 |
| `ThreadRuntime.startTurn` | send 的成功与错误返回均核对回合、会话对象和代次；旧发送不能改写新回合，保留同步完成语义。 |
| `MCPHub`、`OpenAICompatibleSession` | 首次发现取消或 reload 后不会缓存残缺工具清单，下次会重新发现。 |
| `PiSession`、`OmpSession` | 后台缩图、正确 MIME、异步序列化与实际载荷上限，减少大图发送时的界面停顿与队列失败。 |
| `AppModel`、`AppModel+HydraReview`、`VoiceController` | Hydra 独立评审，以及语音检查、连接和收尾期间均保持忙碌与更新阻塞；完成后恢复。评审运行时不能被闲置回收。 |
| `AppModel+Hydra` | 最新落地任务结束后清空句柄，旧任务不会清掉后续任务，恢复闲置运行时回收资格。 |
| `ComposerView.FileIndex` | 搜索检查 60 秒有效期，过期重建并隔离目录切换；兼容 `/var` 与 `/private/var` 目录别名。 |
| `ThumbnailCache`、`AttachmentThumbnail`、预览视图 | 缓存加入文件版本并核对解码前后版本；重新打开读取新内容。缩略图无常驻轮询，只有打开的大图每两秒刷新。 |
| `QuestionTab`、`ThreadRuntime` | 同一请求重开后恢复输入、选择和页码；请求结束后旧弹窗不能写回或提交。 |
| `AttachmentPreview` | 加载失败显示“无法预览”和“重试”，不再无限转圈。 |
| `MarkdownView.StreamingParseCoordinator` | 持续追加时接纳仍属于当前正文前缀的解析结果；替换、缩短和代次变更时拒绝旧结果。 |
| `Git`、`AppModel+HydraMerge` | 准备时固定源树，同步时保留后续非重叠编辑和无关暂存修改；冲突、读取失败或发布失败保留恢复材料并报告。 |
| `AppModel+Hydra`、`StorageUsage` | 已跟踪文件不因缓存目录命名被过滤；Git 拒绝删除有修改的副本时保留目录，恢复补丁使用唯一名称。 |
| `Storage.sweepOrphanedAttachments` | 历史不完整、不可读或存在隔离材料时不删附件；与保存共用队列，并保护扫描期间新提交、尚未落盘的引用。 |
| `CheckoutClaims`、`AppModel` | 归档和删除及时退役 owner，取消归档后允许新 claim；迟到回调不能重新占用已退役记录。 |
| `DiskWriter.writeThread` | 长历史保存减少文件元数据查询，同时拒绝缺失的未修改回合，成功发布后再清理旧文件。 |
| `Localizable.xcstrings` | 本轮新增预览、评审及数据保护提示均补齐简体中文。 |

Git 使用 common-dir 协作租约、真实 index.lock 和具名分支 expected-old 条件更新。最初将 `symref-verify HEAD` 与分支更新放入同一事务，会与 Git 隐式 HEAD reflog 更新冲突，隔离回归已发现并修正；文件写入前执行事务 prepare/abort 预检，最终更新前再次核对符号 HEAD。[Git update-ref 文档](https://git-scm.com/docs/git-update-ref)、[Git files-backend 实现](https://github.com/git/git/blob/v2.56.0/refs/files-backend.c)。

## Thor 收获与剩余边界

复核 10-13 至 10-28 的 13 份实际取得报告，逐份基线和来源见[数据安全报告](audit-2026-10-28-core-data.md)。其中“准备后继续编辑被合并回写覆盖”和“跨 lead/edition 缺少共同仓库锁”仍成立，本轮已修；旧报告中的同步回收写盘、入站图片主线程处理、重复 pending ID 等已在现有版本修过，没有重复计入成果。

以下仍明确保留：

- **MCP 进程登记累计**：旧包装对象保留已确认，实际文件描述符泄漏未测。后代进程终止完成尚无通知接口，本轮未冒险提前注销。
- **Hydra 账本整库重写**：历史 job/request 增长仍会提高保存成本；未读取生产库量化，也未截断历史或拆库。
- **外部编辑竞争**：index.lock 与协作租约约束正常 Git 和 Tivano 写入，不能锁住任意编辑器；Git 读文件到写回之间的极窄窗口仍存在，不能保证该窗口内的外部编辑一定进入恢复快照。绕过锁直接改写符号引用的程序同样不受保护。
- **保留数据的磁盘代价**：dirty worktree 和失败恢复 patch/journal/ref 暂不自动过期；成功同步的 journal/ref 已清理，同一副本快照的补丁及通知不再重复生成；独立任务目录的用户确认回收仍是后续储存管理工作。
- **验证边界**：未连接真实 provider、音频硬件，未完整演练视频、原生 popover 几何/关闭、长列表帧率、多项目远端成功而本地同步失败的整应用编排、断电和离线迁移恢复。
- **图片版本边界**：刻意保留所有被使用版本元数据的覆盖不可识别；持续挂载的缩略图保留快照，重新显示或打开预览才刷新。

这些限制不需要用户补充信息才能交付本轮修复；也不能据此宣称整个产品所有路径已穷尽验证。


## 独立评审后的修订

Finding 1: accepted - 附件 census 移到后台任务；writer queue 只建立扫描代次屏障和逐项检查后删除，扫描期间同步导入和保存可以继续。
Finding 2: accepted - 同一 base/after 快照复用恢复补丁并抑制重复通知；不恢复 force 删除，因为过滤后的 patch 或过去已落地的 after 不能证明当前副本全部内容已保全，dirty 副本仍保留。
Finding 3: accepted - 非 Git 文件夹跳过 Git 筛选与 checkout 扫描；unborn HEAD 的已提交集合为空、索引中的已暂存文件仍保留，损坏的现有引用继续报错。
Finding 4: accepted - 同步的三方合并先在临时索引用 --cached 完成；有冲突不写工作文件，无冲突才将合并结果作为普通 patch 应用。
Finding 5: accepted - 成功三方 apply 删除 before-apply ref；成功同步在 ref 与索引均发布后删除本次恢复 refs 和目录，失败或崩溃恢复资料继续保留。
Finding 6: rejected - 不可读/非 JSON 隔离历史不能可靠枚举附件引用，直接去掉保护会重新引入误删；保留停扫策略并修正误导注释，磁盘代价继续明确记录。
Finding 7: rejected - 当前修复分支已在上一轮移除 symref-verify，使用 symbolic-ref 复核和具名分支 expected-old 事务；本轮没有该调用，不新增不必要的兼容分支。
Finding 8: accepted - 中断时清除已退役草稿；发送期间只暂停编辑，投递成功才退役清空，失败恢复同一份选择、文本和页码。

修订后整应用增量 Debug 构建通过，Apple Git 隔离数据检查 33 项通过，UI 逻辑检查 42 项通过。新增检查覆盖扫描暂停时保存/同步导入继续、unborn HEAD、非仓库识别、冲突不改写文件、成功恢复资料清理，以及失败投递保留草稿和中断后继续回答。该次检查不新增真实 provider、硬件或外部编辑器覆盖。
