# Sidebar + AppModel audit — 2026-10-21

Static source audit only. Ada made the edits below; no builds, tests, lint, app launches, visual checks, or Git commands were run. The lead owns validation. Line references identify the relevant method vicinity, not a validated post-edit line map.

## Fixed

- `Tivano/App/Views/Sidebar/SidebarView.swift:607` — In `listItems`, Today focus no longer obtains the standalone-task list or scans helper statuses. Its attention set consequently stays empty without reading task runtime approvals/questions. Today renders only its own filtered thread list and uses none of these inputs; previously they added work and observation dependencies and could invalidate the item cache without changing Today content. Switching out of Today still rebuilds with the normal inputs. Risk: low; lead should exercise Today → normal → Today with active heads and outstanding approvals. No visual or ordering changes intended; no performance gain measured.
- `Tivano/App/AppModel+Hydra.swift:136` (near `HydraTreeCache.capture`'s successful `inFlight` cleanup) — Check caller cancellation after awaiting a newly created shared capture. The cache-hit and shared-waiter paths already check after their awaits; the creator path previously could return a successful capture after its caller was cancelled. Cleanup still happens first and the shared task is not cancelled, preserving other waiters. Risk: low; cancellation now propagates through the existing throwing API. Lead should cover creator cancellation while another caller awaits the same capture.

## Proposed but not done

- **Checkout synchronization can overwrite intervening edits.** `AppModel+HydraMerge.swift`, `syncDefaultBranch` (around line 995): `mergedFrom` is read from disk after the remote merge completes, rather than from the source bytes used to prepare the merge. An edit made during the remote operation can therefore become the accepted baseline and subsequently be overwritten by `prepared.merged`. The second disk comparison only detects edits after that late baseline. Also, the HEAD equality check and `resetSoft` are separate subprocess awaits, leaving a commit race; failures after the reset can return false after partial mutation despite the “left as it was” message. Impact: possible loss of newer working-file edits or inconsistent local branch/index state. Risk of a quick patch: high. Owner decision: assign a Git-layer transactional/CAS synchronization fix carrying captured source bytes, with concurrent-edit and injected-failure coverage; outside a safe local audit patch.
- **Landing versus merge coordination is narrower than the repository lease.** `AppModel+Hydra.swift:985`, `waitForSettledCheckout`, checks the parent runtime and eventually proceeds on cancellation or timeout; `applyHydraHead` does not acquire the merge's common-directory lease. `AppModel+HydraMerge.swift:292` serializes automatic merges with that lease and its per-model activity registry. Impact: a landing from a different lead targeting the same checkout may overlap merge preparation/synchronization; cancellation/timeout may also end the parent-only wait. This is a source-level coordination gap, not a reproduced corruption. Owner decision: define shared checkout mutation ownership and cancellation semantics across landing and merge; do not merely add another wait that could deadlock with `hydraLanding`.
- **Synchronous work remains on the main actor.** `AppModel.swift:695` can snapshot and synchronously persist each dirty idle runtime during capacity eviction; `commitLibrary:1702` and quit barriers deliberately block for durability. `AppModel+Hydra.swift`, `keepHydraPatch` (around line 1046), writes a potentially large patch synchronously; `syncDefaultBranch` also reads/writes merged file bytes synchronously. Impact: possible stalls proportional to history/file size. Owner decision: prioritize asynchronous eviction and patch/file I/O with explicit durability, lifetime and retry ownership. Do not remove the write barriers to gain responsiveness.
- **Window observer cleanup is absent.** `Window/ThreadWindow.swift:10` registers a local key monitor and never removes its token. `Window/WindowManager.swift:214`, `WindowLiveResize.init`, discards two block-observer tokens. Weak captures avoid retaining the owner, but registrations can remain after transient/capture windows die. Production windows are retained and reused, so this is not evidence of a continuously growing production leak. Owner decision: add teardown with actor-safe ownership and cover capture-window disposal.
- **Skylight's actual renderer is outside this assignment.** `Views/Sidebar/SidebarHero.swift:27` delegates to `Tivano/UI/Common/HeroWeatherView.swift`. The sidebar wrapper contains no explicit occlusion/scene-phase gate; `WindowManager` supplies resize state, not visibility state. This does not prove that the delegated renderer continues drawing when hidden. Owner decision: renderer owner must inspect its timeline/canvas/animation lifecycle and pause policy for occluded/minimized/closed windows, full-window Settings, collapsed sidebar, and Performance Mode, then inspect rendered results. No animation or visual changes made here.
- **Today clock and cache cost remain.** `SidebarView.swift:2680`, `MinuteClock`, is a process-wide task ticking every 60 seconds. Today uses it as a cache key, so Today recomputes its last-24-hours filter/sort each minute; the clock has no visibility-aware subscription lifecycle. `helpersByParent` still runs through its cache before Today list construction. Normal placement changes still allocate fingerprints, and helpers/items compare placement arrays. Impact is unmeasured; this is not evidence of the known severe sidebar-expansion stall. Owner decision: measure before introducing incremental projections or visibility-driven clock ownership.

## Observations

- Read the four assigned performance documents first. They do not establish the entire sidebar-expansion stall as resolved; the retained-scroll replay was only partially accepted. Their historical performance percentages are not measurements of these edits.
- Current `PlacementCache` has an O(1) revision fast path before fingerprint creation; it is newer than the full-scan description in `overnight-update-fanout.md`. Metadata revisions still reach the fingerprint path.
- Sidebar thread rows read live thread/selection cells. Head cards also resolve live head records and reorder those records locally. Holding the `@Observable` AppModel environment is not itself proof that every model mutation rerenders every row.
- Project and standalone list membership comes from `threads(in:)`; the standalone path excludes helpers, while Today deliberately selects all nonarchived non-Hydra-head threads updated within 24 hours. Whether Today should additionally exclude panel/helper chats is a product question, not a safe audit fix.
- Regular library writes are scheduled once, delayed at least 400 ms and spaced at least four seconds apart, then sent to `DiskWriter`. They are not an unbounded restart-on-every-token debounce. Destructive persistence barriers are separate.
- Hydra automatic merges use a model-level queued/running registry and a common-Git-directory lease held with `defer`; runtime merge flags also have `defer` cleanup. No obvious missing lease release on a throwing return was found in that path. The nonoptional branch force unwrap is guarded by the preceding `ownBranch` calculation.
- Existing watchdog, idle-stop and merge-sweep loops check cancellation after sleeping. `waitForSettledCheckout` already avoids a cancelled-sleep busy loop, but intentionally proceeds with landing afterward; its safety policy remains listed above.
- No clear local fix was selected in `AppModel+HydraPairs.swift` or `AppModel+Voice.swift`. Provider/OAuth implementation lifetime is outside these files and remains unverified. Hidden cached chat layout is also outside the assigned sidebar/window wrapper implementation; this audit does not close that issue.
- The requested recent-commit command was not run because this head was explicitly instructed not to use Git. New-feature review used the supplied current source; no claim is made about which of the last eight commits introduced a finding.
- One bounded Nowledge thread search used `nmem --json t search "Tivano sidebar Skylight Hydra merge" --limit 5`; it returned no threads. Conclusions above rely on current source and the assigned documents.
