# 夜间性能优化结果 · 2026-10-17

已完成五个产品文件中的局部优化，保留当前玻璃、字体、动画帧率、文字内容、选择和链接功能。最明确的应用对照：在正常模式、固定窗口下，三会话含本地链接的持续文字回放，进程 CPU 用时减少 **19.9%**、输入处理耗时减少 **18.0%**、主线程驱动回调 p95 间隔减少 **15.3%**。这些是该测试场景的结果，不是整款应用、实际编译吞吐或滚动帧率的统一提升。

## 采用的改动

| 改动 | 具体作用 | 验证与收益范围 |
| --- | --- | --- |
| 原生文本只追加未变前缀后的尾部 | 文字和所有旧属性均未变时复用已有布局；改写或旧样式变化仍走替换；追加时保留原选择 | 同一优化构建 A/B/A，CPU -19.9%；48 组原生前后图像逐像素一致；选择和私有剪贴板导出通过 |
| 历史追加增量绑定 | 新增消息或工具只绑定新行；加载、恢复和移除保持脏标记与弱引用契约 | 20,000 行组件基准：旧追加中位数 61.523 ms，现约 0.002 ms；新值接近计时分辨率，不报告夸张倍数或整机百分比 |
| 复用有效的保存位置 | 内容更新不再重新分配历史位置；结构或位置字典变化后仍执行原算法 | 完整提取快照方法的组件 CPU 减少 60.6%～78.8%，250 组完整快照等价；不包括磁盘耗时 |
| 淡入状态只重分段尾部 | 保留 UTF-8 前缀校验，避免每次展开整段字符数组；重分段旧末尾字符与新增部分，保留改写处理 | 170,493 次范围、透明度、状态和期限对照一致；组件 CPU 减少 71.8%～79.1%，绝对节省较小 |
| 隐藏时间线提前退出滚轮命中测试 | 缓存的隐藏聊天不再重复命中测试整窗 | 1 个可见、8 个隐藏列的检查从 9 次降至 1 次，路由结果相同；不是滚轮 FPS 指标 |

另将空提及名单的返回提前，省掉必然被丢弃的富文本准备；未单独申报收益。

## 仍未证明的事情

原来严重卡顿的完整触发链、实际多编译负载下的滚动帧耗时、真实滚轮和长期内存稳定性仍未闭环。没有证据足以把整件事认定为 WindowServer 自身故障、内存泄漏或标题栏循环。普通 SwiftUI 可选择文字的重复排版仍有明显优化空间，采用前需要解决与现有显示和选择行为的差异。

本轮未重写磁盘保存调度，未采用全局降低子进程优先级。工作区已有的旧 taskpolicy 包装不在本轮收益验证中；之后打包不能把它误当作已验收优化。当前没有合并、打包、安装或发布；已安装正式版保持原包。
