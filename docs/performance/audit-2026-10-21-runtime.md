# Runtime audit · 2026-10-21

## Fixed

- **Late command diffs could overwrite a newer turn’s snapshot cache.** `Tivano/App/Runtime/ThreadRuntime.swift:4245` and `Tivano/App/Runtime/ThreadRuntime.swift:4354`. Failed/interrupted finalization waits only three seconds for command diffs; their tasks continue afterward. A late local capture previously assigned `latestTree` unconditionally, and a late foreign-base lookup assigned `foreignTrees` after a subsequent turn had reset them. Both cache writes now require the captured `runtimeTurnGeneration`. Old tool rows still receive their completed edits. Risk: low, but the lead should exercise a slow diff finishing after the next turn starts; no runtime verification performed.
- **External submission could make an idle follow-up queue churn indefinitely.** `Tivano/App/Runtime/ThreadRuntime.swift:1406`, `Tivano/App/Runtime/ThreadRuntime.swift:1466`, `Tivano/App/Runtime/ThreadRuntime.swift:1088` and `Tivano/App/Runtime/ThreadRuntime.swift:1035`. `startTurn` re-enqueues UI prompts while an external reservation exists. Previously, idle queue draining immediately took that prompt again and scheduled another `startTurn`, repeating until the reservation cleared. Queue draining now waits for the reservation; a pre-turn rejection or deferred successful completion explicitly resumes it. Ordinary completion still uses the existing finalizer drain; failed/interrupted turns retain their existing queue policy. Risk: moderate because this touches the newly added control/queue boundary. Lead validation should cover reservation during history loading, early provider completion before `send` returns, queued UI input, and rejection/interruption.
- **Streaming length bookkeeping survived completed plans/turns.** `Tivano/App/Runtime/ThreadRuntime.swift:4087` and `Tivano/App/Runtime/ThreadRuntime.swift:3261`. Plans added entries to `streamByteLengths` but never removed them on completion; messages/reasoning that ended without individual completion events also remained. Clear a plan’s counter on completion and all remaining counters after the turn’s final flush. No transcript content is removed. Risk: low; late deltas reconstruct their base length from the retained row using the existing fallback. Benefit is bounded bookkeeping retention, not a measured CPU claim.
- **Historical provider patch parsing ran on MainActor.** `Tivano/App/Runtime/ThreadRuntime.swift:2791`. Its unstructured `Task` inherits MainActor, so the synchronous `DiffParser.parse(providerPatch)` used to collect candidate paths still blocked UI despite the later off-main merge. Route it through the existing `@concurrent parseDiff` helper; already supplied `providerFiles` remain reused. Risk: low; inputs are captured values and parsing behavior is unchanged. Main-actor string joining/path collection remain.

## Proposed but not done

- **Save preparation and synchronous control persistence:** `Tivano/App/Runtime/ThreadRuntime.swift:4709` still scans all entries and turns; `Tivano/App/Runtime/ThreadRuntime.swift:1073` synchronously calls `DiskWriter.writeThreadSynchronously` on MainActor. The prior position-reuse optimization is present and was not re-proposed. Estimated impact: potentially substantial for long histories or slow storage, not measured here. An asynchronous flush needs to preserve the external operation’s persistence guarantee and admission/quit barrier; medium/high correctness risk, requires a broader storage/control change.
- **API transcript construction bounds output after building full history:** `Tivano/App/Runtime/ThreadRuntime.swift:2297` builds fragments and joins every assistant run, then retains 40 messages / a 60,000-character budget. Estimated impact: transient allocations and main-thread time proportional to loaded text on API-session creation. Reverse bounded collection could avoid most discarded work, but must preserve assistant-run grouping and exact truncation; medium risk, not changed.
- **Session startup captures configuration across suspension:** `Tivano/App/Runtime/ThreadRuntime.swift:1897` captures the thread and directory before CLI-update/catalog/environment waits. Candidate identity and session epoch protections exist, but this read alone does not establish that all UI route changes are blocked during those waits. Lead should exercise provider/directory changes during warm-up before deciding on a generation/revalidation change. Potential impact: stale launch configuration; risk of an overly broad fix is restarting valid warm sessions. Not reported as a reproduced defect.
- **Voice termination observer lifecycle:** `Tivano/App/Runtime/VoiceController.swift:80` registers `terminationObserver` with a weak self capture, but no removal path is present in this file. Sleep observers are removed in `teardown`. Impact depends on whether AppModel/VoiceController instances are recreated; the callback does not retain the controller. Consider lifetime cleanup if multiple instances occur; low expected impact for one app-lifetime instance. No isolated-deinit/API change attempted.
- **Known hidden-layout, >12-runtime reclamation, inbound image decode/write and final Markdown parsing issues:** no implementation change here. The relevant layout, eviction policy, attachment storage and Markdown parsing implementations are outside the assigned Runtime directory. Runtime event dispatch here consumes already formed tool-image references and message strings; this audit does not establish those other implementations’ current cost or claim those issues resolved. Estimated impact and risk require the owning audits/measurements.
