# Product captures

`scripts/product_captures.py` builds an isolated Debug app, captures the existing product scenes and writes resized PNGs. Run it only when the owner explicitly authorizes launching a capture instance. A request to edit, merge, build or validate code does not authorize captures or an app launch.

## Output location

Each invocation reserves a new directory before building or launching anything:

```text
<artifact-root>/private-artifacts/product-captures/<run-id>/
```

The run ID contains a UTC timestamp, process ID and random suffix. Raw PNGs, JSON framing sidecars and `run.log` live in that directory; resized PNGs go in its `processed/` subdirectory. Printed output paths are absolute.

By default, the script obtains the shared Git directory with:

```sh
git -C <checkout> rev-parse --path-format=absolute --git-common-dir
```

The parent of that shared `.git` directory is the long-lived source checkout; its parent is the artifact root (the wrapper containing the checkout). This also works from a linked worktree: the artifact root is not derived from the worktree's parent, so captures do not accumulate under `.tivano/worktrees`.

Build products remain local to the current checkout/worktree in `build.noindex/product-captures-build`. The Debug app path and capture scenes, isolated app storage/defaults, app arguments and timeout behavior are unchanged. Production libraries and credentials must not be imported into the capture instance.

## Choosing another location

Set `TIVANO_ARTIFACTS_ROOT` to an absolute wrapper path to change the default artifact root. Relative values, including an empty value, are rejected. Both the configured root and the final output location must be outside the current worktree and the long-lived source checkout; checks resolve symlinks as well as checking the supplied path.

Alternatively, use `--output-dir <new-directory>` to select the exact run directory. Relative arguments are interpreted from the working directory. The environment root, if set, must still satisfy its contract. The selected directory must not already exist, even if empty; an existing file, symlink or dangling symlink is also rejected. Parent directories may already exist and missing parents are created as needed.

Path rejection happens before any build or app launch. The final directory is created without `exist_ok`, so two runs selecting the same directory cannot both proceed. A collision is an error, not an instruction to reuse or clear it. Importing the module does not select output paths, create directories, build or launch an app.

## Existing archives

The script never clears a previous capture directory or the shared archive root. Completed and failed runs remain available for deliberate review or separately authorized cleanup. The old `build.noindex/product-captures` location, including any compatibility symlink left by migration, is not reused. Passing that historical symlink as `--output-dir` is an error; choose a fresh external directory instead.

## Privacy prompts on build hosts

macOS stores privacy grants (for example access to removable volumes) per bundle ID and code signature. A capture build that shares the installed Dev bundle ID but is signed ad hoc is identified by its cdhash, so each rebuild replaces the installed Dev's grant and prompts again. Over SSH the login keychain is locked and Developer ID signing fails with `errSecInternalComponent`; build in the logged-in GUI session instead (for example a short-lived launch agent bootstrapped into `gui/<uid>`), so the capture app carries the same Developer ID signature as the installed Dev and reuses its grant. External and removable volumes add a separate Removable Volumes consent for every responsible process that touches them, so the build-host repository, task worktrees, DerivedData and capture/stress run directories belong on the internal disk. Helper binaries compiled for a run (for example `scripts/fixtures/held_drag_driver.swift`) should be built once to a stable path and signed with the same Developer ID (`codesign --force --sign '<Developer ID Application identity>' --identifier <stable-identifier> <binary>`) so their Accessibility/Post Event grant survives recompiles, instead of an ad hoc `swiftc` output that macOS treats as a new app each time.

## Timeline stress runs

In addition to product scenes, `--website-captures <folder>` accepts `TimelineStress` flags in Debug builds:

- `--timeline-stress`: Runs the general chat-timeline jitter, grow, wheel-scroll, thread-switch, window-resize, occlusion and composer stress sequence.
- `--history-scroll`: Seeds 60 turns and exercises slow and fast upward scrolling through earlier history pages.
- `--history-flick`: External-HID-only (`delivery=hid`) trackpad flick run. Seeds 60 turns on an unmounted thread, opens at the settled tail window, writes `history-flick-ready.json` (`pid`, `windowNumber`, `point`, `windowFrame`, `upSign`, `viewport`, `flicks` = 60, `readyAt`, `readyAtWallClock`) to the run directory, waits up to 30s for the external driver's first `.scrollWheel` event on the timeline window, and samples `P = documentHeight - clipMinY` every ~8ms until 1.5s after the last observed event (or budget). Build `scripts/fixtures/flick_driver.swift` once to a stable path and sign it with the same Developer ID as `held_drag_driver` (`swiftc -O scripts/fixtures/flick_driver.swift -o <stable-path>/flick_driver && codesign --force --sign '<Developer ID Application identity>' --identifier dev.tivano.flick-driver <stable-path>/flick_driver`) so its Post Event grant survives recompiles, then run `flick_driver <run-dir> [--drift]` from a process with `CGPreflightPostEventAccess() == true`. Per flick (60 flicks, 120ms apart), the driver warps to `point` and posts `.cghidEventTap` pixel events: `began(0)`, 12 `changed` events every 8ms (~0.25 viewport), `ended(0)`, `momentum begin` + 20 `momentum continue` events every 8ms decaying by 0.85 (~0.25 viewport), and `momentum end(0)`; passing `--drift` moves the pointer and event location on odd-indexed flicks down into the composer (~40pt above the bottom of `windowFrame`) for `changed`, `ended`, and momentum events to exercise gestures whose pointer drifts off the timeline (synthetic HID events are routed by each event's location, so drifted events never reach the timeline: this does not model AppKit's gesture latching and cannot test it). The app's local `.scrollWheel` monitor records every window event, segments flicks (`phase began` to `momentum end`, or `phase ended` when no momentum follows), compares `observed = P_end - P_start` against `injected` observed deltas, marks `clipMinY <= -contentInsets.top + 1` flicks `clamped`, tracks `frameJumps` (`|ΔP - observedDelta| > 40pt`), and writes `stress.json` (`history-flick-summary`), `history-flick-samples.json`, `history-flick.mp4`, and stills (`flick-bottom.png`, `flick-start.png`, `flick-end.png`). Passes (exit 0) when all 60 flicks arrive, at least two history pages load during them, no frame jump exceeds half a viewport (`pageJumps == 0`: a page landing uncompensated) and no stills are missing; per-flick discrepancy and smaller frame jumps are reported only, since overlapping momentum makes their segmentation swing by tens of points (exit 1 on fail, no events, or missing stills; exit 2 when blocked or out of time). Does not prove real finger physics or AppKit-generated momentum from physical hardware, which differs from synthetic momentum events.
- `--mid-scroll` (with optional combinable flags `--mid-scroll-cold`, `--mid-scroll-history`, `--mid-scroll-mix`, `--mid-scroll-resize`, `--mid-scroll-serif`): External-HID-only (`delivery=hid`) bidirectional scroll stress run. By default, seeds a finished 60-turn conversation with height-change-prone content on remount—wrapping 4-column Markdown tables, >120-line fenced code blocks (135–145 lines), turns ending in `turnEnd` with `filesChanged > 0` and `changes == nil` backed by a synthetic `providerDiff`, long multi-paragraph replies, >1-viewport tall turns, and short turns—then opens the thread, loads all history pages until Turn 1 is mounted and `hidden == 0`, centers the reader in the middle of the thread far from both ends, expands one seeded >120-line code block via its `Show all N lines` button (accessibility press with synthetic-click fallback), re-centers, and requires four consecutive stable settle samples (`|ΔdocHeight| <= 0.5pt`, `|ΔclipMinY| <= 0.5pt`, not `historyLoadPending`, visible blocks non-empty) before publishing `mid-scroll-ready.json`; if the settle loop times out, the run logs the reason and exits `2` (`INCONCLUSIVE`) without writing `mid-scroll-ready.json`. Writes `mid-scroll-ready.json` (`pid`, `windowNumber`, `point`, `windowFrame`, `upSign`, `viewport`, `readyAt`, `readyAtWallClock`) and waits up to 30s for the external driver's first `.scrollWheel` event. Build `scripts/fixtures/mid_scroll_driver.swift` once to a stable path and sign it with the same Developer ID (`swiftc -O scripts/fixtures/mid_scroll_driver.swift -o <stable-path>/mid_scroll_driver && codesign --force --sign '<Developer ID Application identity>' --identifier dev.tivano.mid-scroll-driver <stable-path>/mid_scroll_driver`), then run `<stable-path>/mid_scroll_driver <run-dir>` from a process with `CGPreflightPostEventAccess() == true` alongside `TIVANO_TIMELINE_TRACE=<run-dir>/timeline-trace.jsonl open -n -W <Tivano.app> --args --website-captures <run-dir> --mid-scroll [<scenario-flags>]`. The driver posts `.cghidEventTap` pixel events in five stages (90 gestures, 3,500 events total, 120ms between gestures): 20 flicks up (`began`, 12 `changed` every 8ms totaling ~0.25 viewport, `ended`, 21 momentum events decaying 0.85 totaling ~0.25 viewport, `momentum end`), 20 flicks down, 10 alternating slow held drags (`began`, 60 `changed` every 16ms cycling 6–10pt, `ended`, no momentum), 20 flicks up, and 20 flicks down. Optional scenario flags combine with `--mid-scroll` and with each other without changing the default run:
  - `--mid-scroll-cold`: posts `NotificationCenter.default` notification `"TivanoDebugForgetRowMemories"` on the main thread before stage 3 (held drags) and before stage 4; in Debug builds `TableBlock` observes it once and calls `forgetMeasuredWidths()` so remounting tables lay out at width `0` and rewrap above the viewport, deliberately exercising the compensation path (on pre-fix commits without an observer the notification is a no-op).
  - `--mid-scroll-history`: seeds 80 turns with history-calibrated page heights, skips preloading all history, opens at the tail, unpins with a short upward scroll (positioning inside the initial 12-turn window so stage 1's 20 upward flicks trigger multiple earlier-history page loads without hitting Turn 1 or bottom), and settles before writing readiness. History loads are expected rather than `INVALID` (zero pages loaded during measurement fails coverage as `INCONCLUSIVE`), and `evaluateMidScroll` nets out applied `history.syncShift` and `history.restore` (`skipped == false`, `movedY`) from `TIVANO_TIMELINE_TRACE` using the same timestamp alignment and ±5ms boundary-group rule as `timeline.aboveViewportCompensate`, reporting `historyPagesLoadedCount` and `historyCompensations*`.
  - `--mid-scroll-mix`: interleaves additional height-change-prone row kinds with the existing ones—Markdown paragraphs with stable web links (favicon fetch) and bare YouTube links (`LinkTitles` title fetch), user messages containing links (hugging link bubbles), tool calls with image results pointing at generated PNG fixtures in `<run-dir>/mix-fixtures/` across four aspect ratios (`16:9`, `1:1`, `9:16`, `21:9`, both single-image and multi-image strips), >60-step activity/tool groups (66 steps per turn), reasoning blocks (seeded via `rehearse(.reasoningDelta/.reasoningCompleted)`, though finished turns currently filter `.reasoning` in `DisplayBlock.build`), and folded multi-step finished turns (merged multi-reply `FoldedAnswerView`). Pre-seeding `TimelinePresentation` disclosure state directly via API is skipped (`TimelinePresentationStore` is `private` in `ThreadTimeline.swift`); in non-history runs, prep toggles up to two mounted >60-step turns via their `Show this turn's steps` button so persisted disclosure state is exercised across remounts.
  - `--mid-scroll-resize`: during stage 3 (held drags), shrinks the window width by `120pt` (centered so the driver's pointer remains inside the window), waits `1s`, restores the original frame, and waits `1s`. Pairs overlapping the `300ms` window after each resize are counted separately as `resizeWindowShifts*` (and excluded from `sampleGapsDuringInput`), while shifts `> 4pt` outside those windows still `FAIL`.
  - `--mid-scroll-serif`: during stage 4, toggles `TypeScale.shared.serif` on, waits `1s`, toggles it back off, and waits `1s`, treating the `300ms` window after each toggle like resize windows (`serifWindowShifts*`) while still failing on shifts outside those windows.
  Every ~8ms sample records each visible hosted `NSTextView` (`ProseRunView`) and nested horizontal `NSScrollView` (`CodeBlock`/`TableBlock`) frame's `screenMinY = docFrame.minY - clipView.bounds.minY`, live `clipMinY`, margins to top/bottom, and `TimelineScrollTracking.historyLoadPending`. For each consecutive sample pair, the evaluator picks a common anchor block (preferring visible `turn-*` text blocks nearest viewport center, with mounted-block fallback, never switching block mid-pair) and computes `docMinY = screenMinY + clipMinY` and `layoutShift = Δ(docMinY) - compensationMovedY`, where `compensationMovedY` sums `movedY` from `TIVANO_TIMELINE_TRACE` JSONL `"event":"timeline.aboveViewportCompensate"` records (plus `"history.syncShift"` and `"history.restore"` in `--mid-scroll-history` mode) with `skipped == false` whose `t` (ms since `TimelineTrace`'s `CACurrentMediaTime()` origin) is aligned to the sample `CACurrentMediaTime()` clock via the trace file's creation timestamp (`trace.start`) with live trace-tail observation fallback; applied vs skipped compensation counts and skipped reasons are reported (set `TIVANO_TIMELINE_TRACE` so applied compensations are accounted for). The older wheel-event-based `jump = Δ(screenMinY) - upSign * Σ(scrollingDeltaY)` numbers remain in `mid-scroll-samples.json` and `stress.json` as informational only. After the run, the harness confirms the expanded >120-line code block cycled out of `mountedWindow` and back (when not in `--mid-scroll-history`) and reports `expandedBlockRestored` (`true`/`false`/`unavailable`; expected `false` on pre-fix commits, reported only and not part of `PASS`). Writes `stress.json` (`mid-scroll-summary`), `mid-scroll-samples.json` (scenario flags, seeded/skipped row kinds, `turnRowKinds` map, layout-shift counts for `> 4pt`/`> 20pt`/`> 40pt`, top 20 layout shifts naming `blockID`, mapped `rowKind`, and `timestamp`, separate resize/serif 300ms window shift counts and top 20 lists, informational event-jump stats, anchor coverage, recorder audit, applied/skipped above-viewport and history compensations with reasons, pages loaded, and expanded-block check), `mid-scroll.mp4`, and stills (`mid-scroll-middle.png`, `mid-scroll-start.png`, `mid-scroll-end.png`). Verdicts and exit codes: `PASS` (exit `0`) requires `layoutShiftsOver4pt == 0` outside resize/serif reflow windows, `allEventsArrived`, no unexpected history load (and `>= 1` page loaded when `--mid-scroll-history` is set), anchor coverage (`<= 2%` unmatched pairs, zero unmatched pairs with `|rawClipDelta| > viewport/2` during a gesture, zero non-reflow-window sample gaps `> 50ms` during input), recorder finished cleanly with duration covering through the last observed event plus `0.5s`, and all required stills present; `FAIL` (exit `1`) when `|layoutShift| > 4pt` outside reflow windows, events are incomplete, or stills are missing; `INVALID` (exit `1`) if an unexpected history load occurred outside `--mid-scroll-history`; `INCONCLUSIVE` / `TIMEOUT` / blocked (exit `2`) on settle timeout, anchor/history coverage failure, incomplete/truncated recording, budget timeout, or missing foreground desktop/display. `TimelineStress.swift` does not reference fix-only symbols, so the harness cherry-picks cleanly onto pre-fix commits for A/B comparison.
- `--held-drag` (and `--held-drag-hid`): Seeds 24 turns, streams a steady reply (rehearsed deltas with no provider session, looping in external-HID mode across the driver handshake and post-ended tail), and drives a synthetic phased wheel sequence (`mayBegin`, `began`, 1.5s slow upward `changed`, 3.0s resting pause with no events, 1.5s more `changed`, `ended`, then 4.0s more streaming). When `--held-drag-hid` is passed alongside `--held-drag`—or automatically when `cgEvent.postToPid` / `NSApp.postEvent` fail the local `.scrollWheel` monitor's `event.window === window` check—the app writes `held-drag-ready.json` (`pid`, `windowNumber`, `point`, `upSign`, `readyAt`, `readyAtWallClock`) to the run directory and waits up to 30s for real WindowServer-routed events on the timeline window. From a process with `CGPreflightPostEventAccess() == true`, compile and run `scripts/fixtures/held_drag_driver.swift` (`swiftc -O held_drag_driver.swift -o held_drag_driver && ./held_drag_driver <run-dir>`) to warp the cursor and post `.cghidEventTap` phased scroll events. Writes `stress.json` and `held-drag-samples.json` (both ~16ms viewport samples—with stages derived from observed events in external-HID mode—and `observedEvents`) plus `PASS`/`FAIL` violation counts.
  - `--held-drag-quiet-hold` pauses the reply while fingers are down and resumes it after `ended`; with `HELD_DRAG_INTERVAL_MS=120` for the driver the whole hold stays within 48pt of the end. This isolates the drag timeouts: fast growth alone moves any reader out of a follow band. Before the fix this variant snapped the reader back during the pause.
  - **What `--held-drag` / `--held-drag-hid` proves**: Real WindowServer `.cghidEventTap` routing into `ScrollViewProbe`'s local `.scrollWheel` monitor with `event.window === window` matching, `isTrackpadHeld`, `notePhase`, and `.onScrollGeometryChange` unpinning holding the reader's viewport steady across a pause longer than the 2s/3s fallback timeouts while new text streams below.
  - **What it still does not prove**: Real trackpad finger physics (pressure, jitter, AppKit gesture coalescing/momentum curves) or an unattended provider turn (`autoStartedTurnToken` `isRunning` `false -> true` mid-hold), which requires a live provider session rather than rehearsed deltas.
- `--fold-repro` (optional `--fold-repro-scenario all|front|covered|miniaturized|inactive|otherThread|scrolledUp|settings`, default `all`; `--fold-repro-count N`, default `10`; `--fold-repro-hold SECONDS`, default `3`, how long the away scenarios stay away after the fold): Reproduces the folded finished-turn missing-reply bug in an ~890×340pt content window on the isolated capture library. Each repetition opens a fresh Claude thread and rehearses an ~8–12s turn (5 command tools, a ~52-char interim reply, 3 more tools including a `.read` of a PNG path, and a ~770-char Chinese Markdown final reply carrying a unique ASCII `FOLDMARK###` marker streamed in 20–40-char deltas every 16–30ms) across seven visibility/scroll scenarios: `front` (key and pinned throughout), `covered` (opaque borderless window ordered above the main window 1s before `turnCompleted` until 3s after), `miniaturized` (miniaturized 1s before `turnCompleted`, deminiaturized 3s after), `inactive` (`NSApp.hide` 1s before `turnCompleted`, unhide and activate 3s after), `otherThread` (switched to another seeded thread 1s before `turnCompleted`, switched back after the hold), `settings` (Settings › Appearance presented over the chat 1s before `turnCompleted`, dismissed after the hold), and `scrolledUp` (scrolled up 60pt to unpin while the final reply streams, then scrolled to bottom programmatically after folding). At 1.5s after restore (or after `turnCompleted` for `front`), it walks `LinkTextView` instances for the marker and interim reply, records window frames, bounds height vs `height(forWidth:)`, view/ancestor `isHidden`/`alphaValue`/layer opacity, enclosing scroll-view `documentVisibleRect` intersection, clip `minY`, document height and bottom state, calls `scrollToVisible` (+300ms settle) if not visible, captures a window still via ScreenCaptureKit, and measures ink pixels (luminance differing from rect median by `> 0.25`). A repetition fails if the marker view is missing, was not in the unobstructed viewport before that recovery scroll, `scrolledUp` moved less than 30pt, `bounds.height < height(forWidth:) - 1`, any view/ancestor is hidden or has alpha/layer opacity `< 0.05`, still capture fails, or ink pixels are `< 0.5%` of the visible rect area. Writes `fold-repro.json`, appends progress to `run.log`, prints one summary line per scenario, saves PNG stills for every failure and the first pass of each scenario, and exits `0` (no failures), `1` (any failure), or `2` (blocked: invalid arguments, unavailable window/display, or the overall timeout, which grows with the requested repetitions and hold). Optional fault-injection flags test the stuck-height path directly: `--fold-repro-inject-zero` makes `ProseRunRepresentable` report zero height for the marker reply for 0.6s from `turnCompleted` (the stuck state the bug left) and extends the pre-inspection wait from 1.5s to 4.5s, while `--fold-repro-no-heal` turns off `LinkTextView`'s height heal so the injection shows the bug. Under `--fold-repro-inject-zero`, runs are expected to fail with `--fold-repro-no-heal` and pass without it.
- `--subagent-panel-loop`: Starts with 6s CPU/main-stall/still scenarios `idle-baseline` (idle parent, panel closed), `panel-400-quiet` (open 400pt helper, running turn paused after one delta), and `main-quiet` (collapsed helper, paused running parent). It then streams a looping ~15k-character Markdown answer at width 400 with ~40-character deltas every 16ms, width 400 with ~400-character deltas every 50ms, and width 520 at the fast cadence, followed by `after-collapse` and the parent main-chat control. `TIVANO_PROBE_QUIET_ONLY=1` runs only the quiet scenarios and exits 0. `TIVANO_PROBE_OFF` accepts comma-separated `title`, `elapsed`, `stave`, `words`, `card`, `glass`, `dots`; `subagent-loop.json` records the value as `knobsOff`. The first streaming measurement writes `subagent-stream-ready`; outputs include `subagent-loop.json` and `stress.json`. Pass `-AppleShowScrollBars Always` to force legacy scrollers.

Launch the built Debug app directly with `--website-captures <fresh-folder> --subagent-pill-demo` rather than through `scripts/product_captures.py`, which quits its instance.

Launch the built Debug app directly with `--website-captures <fresh-folder> --blank-home [--no-providers]`.

Launch the built Debug app directly with `--website-captures <fresh-folder> --mention-demo`.

Every turn sent in it is rehearsed locally and never reaches a provider. Launch the built Debug app directly with `--website-captures <fresh-folder> --review-demo`.
